# ТЗ и инструкция для агента: Telegram-бот для TutorSys

Документ рассчитан на агента-исполнителя, который не видел предыдущих обсуждений. Все ссылки на код проверены по состоянию репозитория `KovidIvan/TutorSys`, ветка `dev`, коммит `350238c`.

## 0. Цель

Сделать Telegram-бота, который даёт основные функции TutorSys вне сайта: преподаватель смотрит нагрузку и ведёт журнал с телефона, заведующий распределяет нагрузку, зам. декана видит сводку. Бот работает с той же базой данных и теми же правилами доступа, что и сайт. Отдельного API и дублирования бизнес-логики быть не должно.

## 1. Текущее состояние проекта (что уже есть)

**Стек.** Django 5.2, `django-htmx`, `openpyxl`, `python-dotenv`, `psycopg[binary]`, Python 3.12. Интерфейс только на русском. База: SQLite по умолчанию (файл `db.sqlite3`, в Docker том `/app/data`), PostgreSQL включается переменными `DB_ENGINE` и `DB_NAME`. `TIME_ZONE = 'Europe/Minsk'`, `USE_TZ = True`.

**Роли** — группы Django: `deputy_dean`, `head`, `teacher`. Проверка: `has_role(user, name)` в `core/views.py`. Заведующий в демо-данных состоит в двух группах (`head` и `teacher`), у него есть профиль `Teacher`.

**Модели** (`core/models.py`): `Specialty`, `Department` (`head` → `Teacher`), `Group` (академическая), `Curriculum`, `Discipline` (`control_form`: `exam` / `credit` / `none`), `CalcSettings` (единственная запись, `CalcSettings.get()`), `PositionRule`, `Teacher` (OneToOne на `User`), `LoadItem` (виды: `lec`, `pract`, `lab`, `exam`, `credit`, `usr`, `kr`; поле `teacher` может быть пустым), `JournalEntry`, `Adjustment`. Миграции: `0001_initial`, `0002_alter_discipline_control_form`.

**Готовая бизнес-логика, которую нужно переиспользовать** (`core/calculations.py`):

|---|---|
| `teacher_workload(teacher)` | матрица нагрузки по дисциплинам, итоги за осень, весну и год |
| `teacher_total(teacher)` | сумма назначенных часов |

**Тесты:** около 80 (`core/tests.py` — 74, `core/test_importers.py` — 6), запуск `python manage.py test core`. Файлы `test*.py` в пакете `core` подхватываются автоматически.

**Telegram в проекте сейчас нет вообще** (ни кода, ни зависимостей, ни настроек).

### Важные наблюдения, которые влияют на реализацию

1. **Логика зашита во views.** Проверка и создание записи журнала живут внутри `journal_view`, назначение преподавателя внутри `distribution_view`, подготовка данных Excel внутри `export_excel_view` (она сразу возвращает `HttpResponse`). Бот не должен копировать этот код, поэтому нужен этап рефакторинга (раздел 5).
2. **Docker.** `Dockerfile` запускает `migrate`, сид (если нет пользователей) и `runserver` в одном контейнере, `docker-compose.yml` содержит один сервис `web` и том `scale_data` с SQLite. Для бота нужен второй процесс, и общий доступ двух процессов к SQLite требует внимания (раздел 10).
3. **В `docker-compose.yml` переменные окружения перечислены явно**, а `.env` исключён из образа (`.dockerignore`). Токен бота сам в контейнер не попадёт.
4. **Переводы строк смешанные**: `core/views.py` и `README.md` в CRLF, `core/models.py` в LF, `*.sh` и `Dockerfile` в LF (`.gitattributes`). Сохраняйте окончания строк в каждом редактируемом файле, иначе diff будет состоять из тысяч изменённых строк.
5. `.env` и `*.sqlite3` в `.gitignore`. Токен бота нельзя коммитить никогда.

## 2. Принятые решения

| Вопрос | Решение | Почему |
|---|---|---|
| Библиотека | **aiogram 3.x** (проверьте актуальную версию на PyPI и закрепите диапазон `>=X,<4` в `requirements.txt`) | встроенные FSM-диалоги и типизированные callback-данные |
| Доступ к данным | напрямую через Django ORM из того же кода, без HTTP-запросов к сайту | одна база, одни правила, нет второго слоя авторизации |
| Запуск | management-команда `python manage.py run_telegram_bot`, отдельный процесс | не мешает web-процессу |
| Режим приёма | **long polling** (не webhook) | работает без настройки входящих соединений, бот не зависит от веб-сервера и прокси. Так как сайт будет доступен по HTTPS, webhook возможен позже (этап 4), но для прототипа не обязателен |
| ORM из async | обёртка `asgiref.sync.sync_to_async(..., thread_sensitive=True)`; новых зависимостей не нужно (`asgiref` идёт с Django) | ORM синхронный |
| Логика | сервисный слой `core/services/`, общий для сайта и бота | нет дублирования |
| Форматирование | `parse_mode=HTML`, все динамические строки через `html.escape` | в названиях дисциплин бывают `&`, `<`, кавычки |
| Диалоги | FSM в памяти (`MemoryStorage`) | после перезапуска незавершённый диалог просто сбрасывается, на данные это не влияет |

Бот работает **только в личных чатах** (`chat.type == 'private'`). Сообщения из групп и каналов игнорируются.

## 4. Модель данных и миграция `0003`

Добавьте в `core/models.py` (там же, где остальные модели) и создайте миграцию.

```python
class TelegramLink(models.Model):
    """Привязка учётной записи сайта к Telegram-аккаунту (личный чат)."""
    user = models.OneToOneField(User, on_delete=models.CASCADE, related_name='telegram_link')
    telegram_user_id = models.BigIntegerField(unique=True)
    chat_id = models.BigIntegerField(unique=True)
    username = models.CharField(max_length=64, blank=True)   # только для отображения
    notifications_enabled = models.BooleanField(default=True)
    consent_at = models.DateTimeField(null=True, blank=True)   # когда принято согласие (если включено)
    linked_at = models.DateTimeField(auto_now_add=True)

class TelegramLinkToken(models.Model):
    """Одноразовый код привязки. Хранится только хэш."""
    user = models.ForeignKey(User, on_delete=models.CASCADE, related_name='telegram_tokens')
    token_hash = models.CharField(max_length=64, unique=True)   # sha256 от кода
    created_at = models.DateTimeField(auto_now_add=True)
    expires_at = models.DateTimeField()
    used_at = models.DateTimeField(null=True, blank=True)

class TelegramOutbox(models.Model):
    """Очередь исходящих уведомлений; отправляет процесс бота."""
    link = models.ForeignKey(TelegramLink, on_delete=models.CASCADE, related_name='outbox')
    kind = models.CharField(max_length=40)            # assignment, unassignment, overload ...
    text = models.TextField()                          # готовый HTML-текст
    dedupe_key = models.CharField(max_length=120, blank=True, db_index=True)
    created_at = models.DateTimeField(auto_now_add=True)
    sent_at = models.DateTimeField(null=True, blank=True)
    attempts = models.PositiveSmallIntegerField(default=0)
    last_error = models.CharField(max_length=255, blank=True)
```

Зарегистрируйте модели в `core/admin.py` (только чтение для токенов, без показа хэша). Добавьте `verbose_name` на русском, как у остальных моделей.

## 6. Привязка аккаунта (безопасность важнее удобства)

В боте нельзя вводить логин и пароль: они остаются в истории чата. Используйте одноразовый код.

**На сайте** (новая страница `/telegram/`, доступна любому авторизованному пользователю, ссылка в навигационной панели `base.html`):
- показывает статус (привязан/нет, `@username`, дата);
- кнопка «Создать код привязки» (POST, CSRF). Предыдущие неиспользованные коды пользователя аннулируются. Код: 8–10 символов из алфавита без похожих знаков (без `0/O`, `1/I/l`), генерируется через `secrets`, срок жизни 10 минут, одноразовый, в базе только `sha256`;
- код показывается один раз вместе со ссылкой `https://t.me/<TELEGRAM_BOT_USERNAME>?start=link_<код>`;
- кнопка «Отвязать» (удаляет `TelegramLink`).

**В боте:**
- `/start link_<код>` или `/link <код>`: ищется неиспользованный неистёкший токен, при успехе создаётся `TelegramLink` (`telegram_user_id`, `chat_id`, `username`), токен помечается использованным, бот показывает меню по роли;
- ограничение попыток: не более 5 неудачных кодов за 15 минут на один `telegram_user_id` (хранить в памяти процесса достаточно), затем вежливый отказ;
- Telegram-аккаунт привязывается только к одной учётной записи и наоборот (уникальность в БД). Если аккаунт уже привязан к другому пользователю, нужна сначала отвязка;
- `/unlink` отвязывает аккаунт с подтверждением кнопкой;
- неактивный пользователь сайта (`is_active=False`) в боте работать не может.

**Авторизация в каждом обработчике.** На каждое входящее сообщение и каждое нажатие кнопки заново: найти `TelegramLink` по `telegram_user_id` → взять `user` → проверить `is_active` → проверить роль через `has_role`. Не кэшируйте роль в FSM и не доверяйте `callback_data`: идентификаторы из кнопок (`load_item_id`, `teacher_id` и т.д.) всегда перепроверяются на принадлежность пользователю или его кафедре (защита от подмены id).

## 7. Функции бота по ролям

Главное меню строится по реальным группам пользователя. Права складываются: заведующий (группы `head` и `teacher`) видит пункты обоих. Названия кнопок — на русском, с эмодзи в стиле сайта.

### Общие
`/start`, `/help`, `/menu`, `/cancel` (сброс диалога), `/whoami` (ФИО, роль, кафедра), `/unlink`. Если аккаунт не привязан, на любое сообщение бот объясняет, как привязаться.

### Преподаватель (`teacher`)
| Пункт | Что делает | Источник |
|---|---|---|
| 📖 Моя нагрузка | сводка по дисциплинам и видам работ, итоги за осень, весну и год, предупреждения; кнопка «Excel» | `teacher_workload`, `check_teacher_status`, `workload_table` |
| 📝 Добавить запись в журнал | пошаговый диалог (ниже) | `add_journal_entry` |
| 🗒 Мой журнал | последние 10 записей с пагинацией | `JournalEntry` |
| 📊 Мой отчёт | план/факт за текущий год: компактная таблица по месяцам в `<pre>`, итог за год с маркером 🔴 (недовыполнение) / 🟢 (выполнение и перевыполнение) / ⚪ (нет данных); выбор года; кнопка «Excel» | `report_matrix([teacher], year)`, `report_tables` |

**Диалог добавления записи журнала** (FSM):
1. выбор элемента нагрузки из назначенных этому преподавателю (inline-кнопки, по 8 на страницу; подпись «Дисциплина · вид · группа/подгруппа»);
2. дата: кнопки «Сегодня» (`timezone.localdate()`), «Вчера» и ввод вручную `ДД.ММ.ГГГГ`;
3. время начала: необязательно, кнопка «Пропустить», формат `ЧЧ:ММ`;
4. часы: число > 0 и ≤ 999.99, не более двух знаков после запятой (допустите запятую как разделитель);
5. тема занятия: непустой текст (ограничьте разумной длиной, например 1000 символов);
6. подтверждение с итоговой карточкой и кнопками «Сохранить» / «Отмена».

Запись создаётся только вызовом `add_journal_entry`. Защита от двойного нажатия «Сохранить»: после успеха состояние FSM очищается, повторный callback обрабатывается как устаревший.

### Заведующий кафедрой (`head`)
Все операции только в пределах его кафедры (как на сайте).
| Пункт | Что делает | Источник |
|---|---|---|
| 👥 Преподаватели | список со статусом (🟢 ok, 🟡 warning, 🔴 critical), часы и норма; карточка преподавателя с предупреждениями | `_teacher_panel_data` |
| 🧩 Распределение | список нераспределённых элементов нагрузки (фильтры: специальность, семестр, вид), выбор элемента → выбор преподавателя (специализированные сверху с «✓», как на сайте) → назначение или снятие; после действия показывается обновлённый статус преподавателя | `assign_load_item` |
| 📊 Отчёт кафедры | вся кафедра или выбранный преподаватель, выбор года, Excel | `report_matrix`, `report_tables` |
| 🔄 Пересчитать нагрузку | только своя кафедра, с подтверждением кнопкой | `recalculate_department` |
| 📤 Экспорт | «Нагрузка кафедры», «Преподаватели» (Excel-файлом) | `department_load_table`, `teachers_table` |

### Заместитель декана (`deputy_dean`)
| Пункт | Что делает |
|---|---|
| 🏛 Сводка | количество специальностей, кафедр, групп, учебных планов, дисциплин (как `dean_dashboard_view`); по кафедрам: число элементов нагрузки, доля нераспределённых, число преподавателей в статусе critical |
| 🔄 Пересчитать | одна кафедра (выбор кнопкой) или все, с подтверждением |
| 📥 Импорт Excel | **этап 3**, см. раздел 9 |

### Правила оформления сообщений
- Лимит Telegram 4096 символов: длинные списки только постранично (по 8–10 строк, кнопки «‹ Назад / Вперёд ›»).
- `callback_data` не длиннее 64 байт: только короткий префикс и числовые id (например `li:123:p2`). Используйте `CallbackData`-фабрики aiogram.
- Часы показывать округлёнными до сотых (как в обновлённом интерфейсе сайта).
- Устаревшие кнопки (элемент уже перераспределён, диалог сброшен) отвечают понятным сообщением «Данные устарели, откройте раздел заново», без трейсбека.

## 8. Уведомления (этап 2)

Бот-процесс — единственный, у кого есть токен и event loop. Поэтому web-процесс и сервисы **не отправляют** сообщения сами, а кладут их в `TelegramOutbox`; бот раз в `TELEGRAM_OUTBOX_POLL_SECONDS` (по умолчанию 5) забирает неотправленные записи и отправляет.

| Событие | Кому | Где создаётся запись |
|---|---|---|
| Элемент нагрузки назначен или снят | преподавателю | в `assign_load_item` (не в сигналах: пересчёт и админка не должны спамить) |
| Преподаватель перешёл в статус `critical` (больше максимума) | заведующему его кафедры | в `assign_load_item`, не чаще раза в сутки на преподавателя (`dedupe_key`) |
| Недовыполнение месячного плана | не делать в MVP | — |

Требования к рассылке:
- отправляйте только при `notifications_enabled=True`; команда `/notify on|off` переключает флаг;
- при `TelegramForbiddenError` (пользователь заблокировал бота) выставить `notifications_enabled=False`, запись пометить ошибкой;
- при `TelegramRetryAfter` подождать указанное время; максимум 3 попытки, затем `last_error`;
- не более ~1 сообщения в секунду в один чат, глобально не более ~25 в секунду;
- несколько назначений подряд одному преподавателю объединять в одно сообщение (окно 60 секунд по `dedupe_key`).

## 9. Приём и отправка файлов

**Отправка Excel (этап 1).** Файл собирается через `build_xlsx_bytes` в `BytesIO` и отправляется как документ (`BufferedInputFile`). Имена файлов те же, что у сайта (`my_workload.xlsx`, `my_journal.xlsx`, `department_load.xlsx` …).

**Импорт Excel через бота (этап 3, только `deputy_dean`).**
1. Пользователь выбирает «📥 Импорт Excel», затем кафедру (кнопками) и год начала учебного года (число).
2. Присылает `.xlsx` документом. Перед скачиванием проверить `document.file_size` ≤ `MAX_WORKBOOK_SIZE` (2 МБ) и расширение `.xlsx`.
3. Файл скачивается в `BytesIO`, оборачивается в объект с атрибутами `size` и `seek`/`read` (например, `SimpleUploadedFile`, как в `core/test_importers.py`) и передаётся в `import_workload_xlsx(upload, department, year)`.
4. Бот показывает итог: строки, специальности, группы, дисциплины, предупреждения (как `data_import_view`), либо текст `WorkloadImportError`.
5. До вызова импорта нужен шаг подтверждения («Импорт изменит данные кафедры X за год Y. Продолжить?»), потому что импорт обновляет существующие записи.

Документы от пользователей без роли `deputy_dean` и вне диалога импорта игнорируются.

### Сервер и HTTPS

Решение владельца: проект загружается на сервер и открывается по HTTPS. Из этого следует:

1. **`SITE_URL`** (например `https://tutorsys.example.com`, без завершающего слэша) — адрес сайта. Бот использует его для кнопок «Открыть на сайте» (например, из отчёта или распределения) и в тексте привязки. Если пусто, такие кнопки не показываются. Ссылки формируйте одной функцией `site_link(path)`.
2. **Настройки Django за HTTPS** в `nagruzka/settings.py`, управляемые флагом `USE_HTTPS` (по умолчанию `False`, чтобы локальная разработка не ломалась). При `USE_HTTPS=True`:
   - `SESSION_COOKIE_SECURE = True`, `CSRF_COOKIE_SECURE = True`;
   - `SECURE_PROXY_SSL_HEADER = ('HTTP_X_FORWARDED_PROTO', 'https')` (сертификат обычно держит обратный прокси: nginx, Caddy или Traefik, и передаёт заголовок);
   - `CSRF_TRUSTED_ORIGINS` берётся из окружения (поддержка уже есть в `settings.py`), в `.env` нужно указать `https://<домен>`, иначе POST-формы, включая создание кода привязки на `/telegram/`, будут отклонены с ошибкой CSRF;
   - `ALLOWED_HOSTS` содержит домен, `DEBUG=False`, `SECRET_KEY` уникальный.
   HSTS и редиректы с HTTP на HTTPS настраиваются на прокси, в рамках этой задачи их не добавляйте.
3. **Страница привязки `/telegram/` и код привязки** работают только в защищённом соединении на сервере: код нельзя показывать по обычному HTTP.
4. **Исходящие соединения.** Бот должен иметь доступ с сервера к `https://api.telegram.org` (порт 443). Для polling входящие порты открывать не нужно. Проверьте это в README (команда проверки, например `curl https://api.telegram.org`).
5. **Прокси и бот.** Бот-процесс не обслуживает HTTP-запросы, ему не нужен домен или сертификат. Обратный прокси перенаправляет трафик только на сервис `web`.
6. **Важное предупреждение для деплоя** (не входит в эту задачу, но владельцу нужно знать): текущий `Dockerfile` запускает сайт командой `runserver --insecure`, это сервер разработки. Для реального сервера лучше заменить его на `gunicorn` и раздачу статики через прокси. Агенту это менять не нужно, если владелец отдельно не попросит; отметьте в описании PR.
7. **Webhook** (по желанию владельца, этап 4): при наличии HTTPS его можно добавить отдельным маршрутом Django с секретным токеном в пути и заголовком `X-Telegram-Bot-Api-Secret-Token`. В MVP не делать.

### Что нужно от разработчика, который настраивает сервер

Сервером занимается другой человек, поэтому ТЗ не привязано к конкретному прокси или хостингу. Ему достаточно обеспечить следующее (этот список перенесите в README отдельным разделом):

1. Сайт открывается по HTTPS на домене, в `.env` заданы `ALLOWED_HOSTS`, `CSRF_TRUSTED_ORIGINS=https://<домен>`, `SITE_URL`, `USE_HTTPS=True`, `DEBUG=False`, уникальный `SECRET_KEY`.
2. Прокси передаёт заголовок `X-Forwarded-Proto: https` на сайт.
3. С сервера есть исходящий доступ к `api.telegram.org:443`.
4. Процесс бота (`python manage.py run_telegram_bot`) запущен постоянно в одном экземпляре (отдельный сервис Docker, unit systemd или аналог) и перезапускается при падении.
5. Токен бота лежит только в `.env` или в секретах сервера, в репозиторий не попадает.
6. Для постоянной работы желательна PostgreSQL: бот и сайт пишут в одну базу, а SQLite при двух процессах может блокироваться.

**Нюансы запуска:**
1. **Порядок старта.** Миграции выполняет контейнер `web`. Команда бота должна при старте проверить, что нет непримененных миграций (`MigrationExecutor`), и подождать, а не падать.
2. **SQLite и два процесса.** Одновременная запись из `web` и `bot` в один файл может дать `database is locked`. Минимально: в `DATABASES['default']['OPTIONS']` для SQLite задать `'timeout': 20`, держать транзакции бота короткими. В README указать, что для постоянной работы рекомендуется PostgreSQL (он уже поддерживается проектом).
3. **Один экземпляр бота.** Два процесса с одним токеном в режиме polling конфликтуют (`TelegramConflictError`). Не запускайте второй экземпляр, а при конфликте выводите явное сообщение.
4. **Остановка.** Корректно обрабатывать SIGTERM/Ctrl+C (закрывать сессию бота).

## 11. Безопасность (чек-лист)

- Токен только в окружении; в логи не попадают токен, коды привязки и тексты сообщений пользователей. Логируйте `telegram_user_id`, тип события, результат.
- Код привязки: случайный, короткоживущий, одноразовый, хэшируется; ограничение неудачных попыток.
- Роль и принадлежность данных проверяются на каждый апдейт на стороне сервера (раздел 6).
- Изоляция кафедр такая же, как на сайте: заведующий не видит и не меняет чужую кафедру ни через кнопки, ни подменой `callback_data`.
- Все пользовательские и «чужие» строки (названия дисциплин, темы занятий, ФИО) проходят через `html.escape` перед отправкой.
- Excel-файлы строятся тем же кодом, что на сайте, с защитой от формул (`_fill_sheet`).
- Ограничение размера и типа входящих файлов (раздел 9).
- В боте нет действий, удаляющих данные (удаление преподавателей, дисциплин и т.п. остаётся только на сайте).
- ФИО преподавателей и учебные часы уходят в Telegram: для прототипа это разрешено владельцем, но управляется настройками приватности (раздел 11а).

## 11а. Приватность: решение владельца и как сделать её настраиваемой

Решение владельца: для демонстрационного прототипа передача ФИО и часов преподавателей через Telegram **допустима**. Но это решение должно быть обратимо без переписывания кода, поэтому заложите следующее с самого начала.

1. **Единая точка форматирования персональных данных.** Все имена преподавателей в сообщениях бота выводятся только через функцию `display_name(teacher, viewer)` в `core/tgbot/texts.py`, а чужие часы только через `display_hours(...)`. Нигде в обработчиках нельзя подставлять `teacher.full_name` напрямую. Тогда смена политики это правка в одном месте.
2. **Режим приватности `TELEGRAM_PRIVACY_MODE`:**
   - `full` (по умолчанию для прототипа): ФИО и часы показываются полностью, в рамках прав роли;
   - `masked`: вместо ФИО инициалы («Иванов А.П.»), заведующему и преподавателю по-прежнему доступны только данные в пределах прав роли, а в уведомлениях и отчётах нет тем занятий и причин корректировок;
   - `minimal`: бот показывает только обезличенные счётчики и статусы, без ФИО и тем занятий (подробности только на сайте).
   Режим читается из переменной окружения при запуске бота, для смены достаточно изменить `.env` и перезапустить процесс бота. Это нужно описать в README.
3. **Согласие при привязке (`TELEGRAM_REQUIRE_CONSENT`).** Если включено, перед завершением привязки бот показывает короткий текст («Бот будет присылать вам учебные данные: нагрузку, часы и ФИО коллег в пределах вашей роли. Данные передаются через сервис Telegram») и кнопки «Согласен» / «Отмена». Время согласия записывается в `TelegramLink.consent_at`. Без согласия привязка не создаётся. Текст согласия лежит в `texts.py` и легко заменяется.
4. **Полное отключение.** Пустой `TELEGRAM_BOT_TOKEN` выключает бота целиком, сайт не затрагивается. На странице `/telegram/` показывается «Бот не настроен».
5. **Удаление данных.** Отвязка (на сайте или `/unlink`) удаляет `TelegramLink` и все записи `TelegramOutbox` этого пользователя. Отправленные записи очереди старше `TELEGRAM_OUTBOX_KEEP_DAYS` дней бот удаляет сам. Management-команда `python manage.py telegram_unlink_all` отвязывает всех сразу (на случай смены политики).
6. **Минимум хранения.** В базе нет содержимого переписки пользователя с ботом, только привязка и очередь исходящих. Тексты сообщений пользователей в логи не пишутся.

## 12. Тесты

Новые файлы `core/test_telegram_*.py`, запуск `python manage.py test core`. Сеть Telegram в тестах не используется.

**Архитектурное требование для тестируемости:** вся логика формирования ответов (тексты, списки кнопок, решения «что показать») должна быть в синхронных функциях без aiogram-объектов, а обработчики остаются тонкими. Тогда основная часть тестов обычные `TestCase`, а обработчики проверяются лёгкими тестами с `AsyncMock` вместо `Message`/`CallbackQuery`.

Обязательные сценарии:
1. **Сервисы:** `add_journal_entry` (успех и каждый вид ошибки: нет даты, часы 0 / отрицательные / слишком большие / `NaN`, пустая тема, чужой элемент нагрузки); `assign_load_item` (успех, снятие назначения, чужая кафедра, преподаватель чужой кафедры, пользователь без роли `head`).
2. **Регрессия сайта:** все существующие тесты проходят после этапа 0.
3. **Привязка:** успешная привязка; просроченный код; повторное использование кода; чужой код; лимит неудачных попыток; один Telegram — один пользователь; отвязка; неактивный пользователь.
4. **Права:** преподаватель не может вызвать функции заведующего и зам. декана; заведующий не видит чужую кафедру; подмена id в `callback_data` отклоняется.
5. **Форматирование:** HTML-экранирование (название дисциплины с `<`, `&`), разбиение длинных списков, длина `callback_data` ≤ 64 байт.
6. **Диалог журнала:** корректный путь создаёт ровно одну запись; неверный ввод на каждом шаге не ломает диалог; двойное «Сохранить» создаёт одну запись; `/cancel` сбрасывает состояние.
7. **Outbox:** запись создаётся при назначении и снятии; не создаётся при пересчёте; `dedupe_key` склеивает повторы; при `notifications_enabled=False` не отправляется; ошибка `Forbidden` отключает уведомления.
8. **Приватность:** в режимах `full`, `masked`, `minimal` в сообщениях нет данных, которых режим не допускает (проверка по ФИО и темам занятий); без согласия привязка не создаётся, когда `TELEGRAM_REQUIRE_CONSENT=True`; отвязка удаляет `TelegramLink` и очередь пользователя; `telegram_unlink_all` отвязывает всех.
9. **HTTPS и ссылки:** при `USE_HTTPS=True` включаются secure-cookie и заголовок прокси; `site_link` строит корректные адреса и не добавляет кнопки при пустом `SITE_URL`.
10. **Файлы:** сборка Excel совпадает по содержимому с веб-экспортом; импорт через бота отвергает слишком большой и неверный файл.

Дополнительно выполните ручной прогон с реальным тестовым токеном по сценарию из раздела 14 и приложите результат к PR.

## 14. Порядок работ и критерии приёмки

| Этап | Содержание | Готово, когда |

**Ручной сценарий приёмки (этап 1)**, на демо-данных (`python manage.py shell -c "from core.seed import run; run()"`, пароль демо-аккаунтов `pass123`):
1. На сайте войти как `teacher`, открыть `/telegram/`, создать код, в боте выполнить `/start link_<код>` → бот показывает меню преподавателя.
2. «Моя нагрузка» показывает те же числа, что `/workload/`. «Добавить запись» создаёт запись, которая видна на `/journal/` и попадает в факт отчёта.
3. Повторное использование того же кода отклоняется; `/unlink` отвязывает аккаунт.
4. Войти как `head`, привязать второй Telegram-аккаунт: в «Распределении» назначить элемент преподавателю, на сайте на `/distribution/` назначение отображается; попытка действия над чужой кафедрой невозможна.
5. Войти как `deputy_dean`: «Сводка» совпадает с `/dean/`; «Пересчитать» работает с подтверждением.
