# Задача: довести проект TutorSys до запускаемого демо

## Контекст
Репозиторий: https://github.com/KovidIvan/TutorSys, ветка main.
Django 5 (<6) приложение `core` для учёта учебной нагрузки кафедр.
Роли (группы Django): `deputy_dean`, `head`, `teacher`.
Стек: Django, HTMX (CDN), Bootstrap 5 (CDN), openpyxl, python-dotenv. База: PostgreSQL по `.env`.
Реализованы модели, админка, расчёт нагрузки (`core/calculations.py`), распределение, журнал, отчёт план/факт, экспорт в Excel, демо-данные (`core/seed.py`).
Остался этап 9 (полировка и демо), а проект сейчас не запускается и содержит баги.

- Не коммитить секреты.

## Порядок работы
Выполнять строго по блокам. После каждого блока делать отдельный коммит и кратко отчитываться.

### Блок 1. Каркас проекта и гигиена репозитория
В репозитории отсутствуют `manage.py`, `nagruzka/settings.py`, `nagruzka/wsgi.py`, `nagruzka/asgi.py`, `nagruzka/__init__.py`, `core/__init__.py`, `core/apps.py`, `core/migrations/`.
1. Создать недостающее (`django-admin startproject nagruzka .` в корне, существующий `nagruzka/urls.py` сохранить).
2. Настроить `settings.py` по `SETTINGS_FRAGMENT.txt` и `SETTINGS_UPDATE_GUIDE.txt`:
   - `core` и `django_htmx` в `INSTALLED_APPS`, middleware `HtmxMiddleware`;
   - чтение `.env` через python-dotenv;
   - `LOGIN_URL`, `LOGIN_REDIRECT_URL`, `LANGUAGE_CODE='ru'`, `TIME_ZONE='Europe/Minsk'`;
   - БД: PostgreSQL из `.env`; если `DB_ENGINE` не задан или `DB_NAME` пуст, fallback на SQLite `db.sqlite3`.
3. Проверить, что в `nagruzka/urls.py` есть маршруты login/logout (иначе добавить `django.contrib.auth.urls`) и шаблон `registration/login.html`, если его нет.
4. `.gitignore`: добавить `env/`, `.venv/`, `.env`, `db.sqlite3`, `__pycache__/`, `*.pyc`. Выполнить `git rm -r --cached env .env`. Создать `.env.example` без реальных значений.
5. Сообщить пользователю, что `SECRET_KEY` и `DB_PASSWORD` из старого `.env` были в git-истории и их нужно сменить. Историю не переписывать без отдельного согласия.
6. `makemigrations core`, `migrate`. Критерий: `python manage.py check` без ошибок и `runserver` стартует.

### Блок 2. Исправление багов
1. **NameError в `check_teacher()`** (`core/calculations.py`): `Sum` импортирован только внутри `teacher_total`. Вынести `from django.db.models import Sum` на уровень модуля.
2. **Экзамен и консультация схлопываются.** В `calc_department_load` для экзамена создаются два элемента с одним ключом `(discipline, kind, group, subgroup_no)`. `recalculate_department` находит их как один и перезаписывает часы.
   - Различать их: либо новый `kind='consult'` (добавить в `LoadItem.KIND_CHOICES`, `Adjustment` использует те же choices), либо объединить в один элемент (часы студентов + консультация). Выбрать более простой вариант и записать решение в README.
   - Проверить, что контрольный тест 277.95 ч остаётся зелёным. Добавить тест «пересчёт не теряет часы и сохраняет назначенного преподавателя».
3. **Распределение (HTMX), `core/views.py::distribution_view`:**
   - POST должен возвращать partial `core/_teacher_panel.html` (с обновлёнными итогами), а не `redirect` на всю страницу. Для не-HTMX запроса оставить редирект.
   - Использовать готовый `load_teacher_panel_view` или общий хелпер, не дублировать код.
   - Проверять, что `load_item.discipline.department` равна кафедре текущего `head`, а выбранный `teacher.department` равна ей же. Иначе 403.
   - Заменить голый `except:` на `except Teacher.DoesNotExist`.
4. **Статус преподавателя** (`check_teacher_status`): `critical`, если часы больше максимума; `warning` при любых других замечаниях; `ok`, если замечаний нет. Не считать статус по числу предупреждений.
5. **Отчёт план/факт** (`report_for_teacher`): убрать деление годового плана на 9, применяемое ко всем 12 месяцам. Минимально допустимо: план распределяется равномерно по месяцам семестра дисциплины (семестр 1 — сентябрь–январь, семестр 2 — февраль–июнь), в остальные месяцы план 0. Описать допущение в README.
6. Для каждого исправления добавить или обновить тест.
