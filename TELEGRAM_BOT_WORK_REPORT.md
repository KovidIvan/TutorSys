## Цель

Реализовать Telegram-бота, связанного с веб-системой TutorSys, чтобы пользователи могли получать доступ к функциям по своей роли и выполнять основные рабочие операции через личный чат.

## Что реализовано

- **Подключение аккаунта:** страница `/telegram/` создаёт одноразовый код с ограниченным сроком действия; код хранится в базе в виде SHA-256-хэша. Поддержано подтверждение привязки и согласие пользователя.
- **Привязка пользователей разных ролей:** Telegram-аккаунт может привязать любой авторизованный пользователь сайта, не только преподаватель. Доступность команд и пунктов меню определяется актуальными группами Django.
- **Авторизация и управление подключением:** команды `/start`, `/help`, `/menu`, `/whoami`, `/cancel`, `/unlink` и `/notify on|off`; обработчики проверяют права пользователя, а не полагаются на старую клавиатуру.
- **Функции по ролям:** преподавателю доступны сведения о своей нагрузке и журнале; заведующему кафедрой — сведения о преподавателях, распределение нагрузки, снятие назначений и отчёты; заместителю декана — предусмотренные ботом сводки и просмотр данных с постраничной навигацией.
- **Отчёты и уведомления:** реализованы формирование Excel-отчётов с соблюдением режима приватности и отправка уведомлений через outbox.
- **Запуск и развёртывание:** добавлена команда `manage.py run_telegram_bot`, настройки окружения, интеграция отдельного процесса бота в Docker Compose и вспомогательные команды запуска для Windows/Linux; инструкции внесены в README.

## Исправления привязки и роли заведующего

1. Исправлен callback согласия: идентификатор Telegram берётся у пользователя, нажавшего кнопку согласия, а не у бота-автора сообщения. Это устраняет ошибку, при которой привязка могла завершиться не для того Telegram-аккаунта.
2. Страница привязки доступна любому авторизованному пользователю, включая аккаунт без профиля преподавателя.
3. Если при выборе старой кнопки раздела заведующего у привязанного аккаунта нет этой роли, бот теперь объясняет, что права проверяются у связанной учётной записи, и отправляет меню, сформированное по текущим ролям. Если аккаунт вообще не привязан, выводится отдельное сообщение о необходимости привязки.
4. Добавлен регрессионный тест, проверяющий обновление устаревшего меню заведующего для пользователя с текущей ролью преподавателя.

## Настройка и запуск

В локальном `.env` задаются `TELEGRAM_BOT_TOKEN` и `TELEGRAM_BOT_USERNAME` (без кавычек, если в значении нет пробелов), а также при необходимости `SITE_URL` и настройки режима приватности. Перед первым запуском нужно применить миграции:

```powershell
python manage.py migrate
python manage.py run_telegram_bot
```

Бот запускается отдельным процессом; веб-сервер TutorSys должен работать независимо. После изменения групп пользователя или настроек запущенный процесс следует перезапустить. В Telegram команды `/whoami` и `/menu` помогают проверить привязанный аккаунт, распознанные роли и актуальную клавиатуру.
